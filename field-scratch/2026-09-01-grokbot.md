### 2. Matthew Berman — 87 — telegram-inbox-bridge — education? **no**
- Who: Matthew Berman (YouTube "11 INSANE Use Cases for Grok Bot", https://youtu.be/5CSXUsljJ_E)
- Score: **87 awesome**
- URL: https://grokbot.dev/use-cases/telegram-inbox-bridge/
- Date: added 2026-08-21
- What: inbound Telegram front door for a Grok Bot fleet using your own BotFather bot. Native Slack exists; Telegram does not. Pattern: local listener 127.0.0.1:8787 → spool files → **cron routine drains spool**, not a Grok Bot webhook routine.
- Gate/failure/what they kept:
  - Grok Bot webhook routine is the wrong front: agent cannot see public URL/sender key; opening it can **crash the UI** (trigger has no platform). Use cron, not webhook.
  - Cloudflare quick-tunnel `*.trycloudflare.com` often fails Telegram's checker ("Failed to resolve host") even when the tunnel works locally → smee.io (or similar) relay.
  - Once setWebhook is live, getUpdates **409s**. Never poll getUpdates in webhook mode.
  - sendChatAction typing expires ~5s; refresh every ~4s until reply.
  - Hand-rolled Python MCP that is not NDJSON/Content-Length compatible **times out** when Grok Bot hosts it; use official Node SDK.
  - Supervisor must kill old PID on restart or stale code keeps serving.
  - Drain is ~once a minute (not instant like OpenClaw). Quiet in Grok Bot chat if spool empty. Never print token/secret/public URL.
- Mechanism tags: quiet-when-nothing, cron-not-webhook, killed-claim (webhook-UI-crash, tunnel-resolve, getUpdates-409, MCP-timeout), human-gate (own BotFather, chat-id allowlist)
- Practice summary: named, operational, failure-rich. Off education. Portable for any inbound channel that isn't native. Not roster unless Wedge wants a phone front door.
