Create an issue in the repo as <second-account> , assigned to <my-account> . Wait several minutes. ## STAFF @deanrie · 2026-09-16T05:59:58.162Z · #5
Hey, thanks for the detailed report. Extra thanks for the timings table and for checking access, the routine itself, and notifications upfront. Main point first: your setup is correct. This isn’t a configuration issue on your side. It’s a known issue on our side that we’re already tracking. The GitHub issue assigned trigger currently doesn’t fire for github.com repositories, so the routine won’t start no matter how the assignee is set. Your access, routine, and filter are fine. On your questions: Yes, by design the routine should also trigger when a collaborator creates an issue with an assignee set right away. In that case GitHub sends a separate assigned event. The trigger listens specifically to the assignment event assigned. The filter (by @user ) checks who assigned it (the assigner), not the author or the assignee. In your case the collaborator is both the creator and the assigner, so the setup matches. There’s currently no user-facing log of received or non-matching routine events. Agree it would be useful, I’ve passed this on as feedback. Temporary workaround: since webhook-routine doesn’t work for you due to 171324, the most reliable option right now is a scheduled routine. For example, every 15 minutes on weekdays, have the Bot check the repo for open issues assigned to you that it hasn’t processed yet, then handle them. If you prefer, a Slack trigger also works. I can’t share an ETA for the event trigger fix yet, but I’ll post an update here when I have one.
