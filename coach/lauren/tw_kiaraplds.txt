 Last week I had a flight to Austin. I had planned to use the flight over to put a COBOL mainframe application through the migration factory I have been working on, but my flight did not have Starlink yet, so I could not run it myself.
A migration is a mix of technical work and knowledge work. A slice does not move along the migration factory line until the structured artefacts for that phase have been checked and agreed. That control model was inspired by 
@poteto
 pStack, and by the rigorous gates she puts across her agents.
I used the limited wifi I had to teach a team of 
@bot
 Grok Bots how the factory runs, and how I review each of the six phases. I then asked them to run it on that application, and authorised them to approve decisions on my behalf while I was offline. They can start Cursor cloud agents, they have the same context and systems I do, and they continue to work when the laptop is shut.
By the time I arrived in Austin the migration was finished and all characterisation tests were green. Each slice had been reviewed against the same checks I use. I then read every audit record across the 7 assembly stations myself, and I agreed with each decision that had been made.
The screenshots show the Grok Bot channel where that work ran, and the migrated mainframe application.
The run has firmed up a hypothesis for me. This generation of technology modernisation is the last that should be organised as a programme. The operating model that follows is one in which an AI software factory is responsible for evergreening the stack with a mixture of both technical and knowledge work agents operating the assembly line stations.
If anyone is interested can write up more on the factory and how I trained them.
