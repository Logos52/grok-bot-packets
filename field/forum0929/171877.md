## #5 deanrie [STAFF] · 2026-09-16T14:19:42Z
Hey, thanks for the detailed report and for checking the server ahead of time with the official MCP SDK and Grok web. That really narrows things down. Here’s the full redirect_uris array that gets sent during Dynamic Client Registration (it’s the same for desktop and Cloud Agents): cursor://anysphere.cursor-mcp/oauth/callback https://www.cursor.com/agents/mcp/oauth/callback (Cloud Agents / web) http://localhost:8787/callback (desktop loopback) Grok Bot desktop authorizes via entry 3 (localhost loopback), so your Cloudflare settings for entries 2 and 3 are already correct. The /bot/ callback you added isn’t related to desktop registrations. It’s harmless, but not needed. The issue is entry 1. Cloudflare Managed OAuth only allows https in “Allowed redirect URIs”, so you can’t allowlist cursor:// there at all, and Cloudflare rejects the entire registration with redirect_uri is not allowed by the account configuration . This isn’t caused by your setup. Your server and config aren’t the problem here. This is an issue on our side that we’re tracking. The goal is for registration to only send https and localhost callbacks. Once that ships, your current Cloudflare configuration should work without any changes. I’ll post an update here when we have one. Workaround for now: since it’s your server, you can bypass OAuth using a Cloudflare Access service token. In Zero Trust, create a service token, add a Service Auth policy to the app, and connect MCP using the CF-Access-Client-Id and CF-Access-Client-Secret headers instead of OAuth (the server needs to accept identity from the Access JWT via the service token). If you try it, let me know whether the tools load.

## #8 deanrie [STAFF] · 2026-09-17T18:32:46Z
Hey, you dug in the right direction, and I need to correct my previous recommendation. Right now, there’s no safe way in Grok Bot to set a custom HTTP header like CF-Access-Client-Secret . Connectors in Grok Bot authenticate only via OAuth. Tokens are stored on the connector backend, and the Bot calls tools without receiving them. There are no owner-only settings, no separate secrets form, and no secret reference for arbitrary headers in the Grok Bot UI. AddMcpServer.headers does exist at the API level, but there’s currently nowhere to enter a secret there safely, not via chat and not via model-visible tool args. So the service token via headers approach I suggested applies to the mcp.json editor, but not to the current Grok Bot. Sorry about the confusion, that workaround isn’t available in the Bot yet. So the practical path for you is to remove the legacy cursor:// callback from the OAuth registration. This is on our side, and we’re tracking it. The goal is still the same, only https and localhost callbacks should be sent during registration, and then your current Cloudflare setup will work without changes. I can’t share an exact timeline, but I’ll reply in this thread when there’s an update.

## #11 deanrie [STAFF] · 2026-09-25T11:33:52Z
@Vaughan-g-aus - yep, this is the exact same issue described above. Cloudflare Access Managed OAuth only accepts https in Allowed redirect URIs, plus the localhost or loopback toggles, and you can’t allowlist cursor://anysphere.cursor-mcp/oauth/callback there. Because of that, Cloudflare rejects the whole DCR registration. This is on our side, not your config, and we’re tracking it. The goal is that registration only sends https and localhost callbacks, and then your current Cloudflare setup will work with no changes. I can’t share a target version yet, but I’ll update this thread when there’s news. @Charles_Wood - thanks, great callout on RFC 8252 §8.3.
