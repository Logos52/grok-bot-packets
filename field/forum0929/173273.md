## #1 bjohnson1 · 2026-09-28T22:56:38Z
Where does the bug appear (feature/product)? Grok Bot Describe the Bug It appears that Grok Bot (in addition to Cursor cloud agents) may not respect the mcpServers optional field in the Cursor Plugin manifest ( Plugins Reference | Cursor Docs ) used to override the default mcp.json discovery. Both Grok Bot and Cursor cloud agents failed to authenticate when a marketplace-listed plugin was added with a MCP config file named differently (even though it was provided in that optional manifest field). This does not appear to impact local Cursor agents. Renaming the MCP config file to the standard “mcp.json” at the top level of the plugin repo + removing the mcpServers optional field from the manifest resolved the issue. Steps to Reproduce Add a marketplace listed plugin to Grok Bot/Cursor which provides the optional mcpServers field in the Cursor plugin manifest, with an MCP config file named something other than “mcp.json”. Attempt to authenticate from Grok Bot or a Cursor cloud agent. Operating System MacOS Version Information Grok Bot v0.61.0 Cursor v3.22.12 Does this stop you from using Cursor No - Cursor works, but with this issue
