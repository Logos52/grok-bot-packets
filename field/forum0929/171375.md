## #10 deanrie [STAFF] · 2026-09-28T05:24:45Z
Hey, good question. The difference really isn’t always obvious. If I had to put it very simply, here’s how to think about the split. Cursor Projects are for longer work inside a codebase. You talk to a coordinator agent. It doesn’t write code itself, it plans, delegates work to agents, and brings results back for review. Each Project is tied to a repo, runs on Cloud Agents, and keeps shared context that builds up over time and syncs between cloud and local machines. This is for a feature with multiple PRs, a migration, a full app, or anything that lasts longer than a single chat. More details: Projects | Cursor Docs Grok Bot is persistent bots, AI teammates with names, roles, and their own accumulated context. Each one runs on its own cloud computer with a browser, file system, and terminal. It’s stronger when the task goes beyond the repo, like multi-step work across apps and websites, including non-coding work. More details: Grok Bot | Cursor Docs A practical split that usually works is this. Code and anything centered around the repo goes in Projects. Orchestrating tasks that spill into other tools or services, or aren’t about code, goes in Grok Bot. On the point that they don’t share context directly, that’s a fair callout. If there’s an update on that, I’ll post it in the thread. @Picasso_shief re your request about what Projects are, check the description above and the docs link. It explains how the coordinator and shared context work.
