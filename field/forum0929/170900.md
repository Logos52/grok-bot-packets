## #7 mohitjain [STAFF] · 2026-09-08T08:19:17Z
Hey @jsolly , thanks for the report. This isn’t intended behavior, and it’s an issue we’re already tracking. The badge only counts an OAuth sign-in as “authenticated,” so connectors that don’t use OAuth (Cloudflare docs is fully public, Fastmail uses an API token) show “needs auth” even though they’re connected and their tools run. It’s cosmetic - those tool calls should still work. Authenticate just confirms the connection and a restart re-reads the same state. If the badge is getting in the way (e.g. other bots skipping the connector), removing the account entry for it under Settings → Plugins clears it - but it comes back if Authenticate runs on it again, so best to leave those two as-is. I’ll follow up here when there’s an update.
