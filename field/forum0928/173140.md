Where does the bug appear (feature/product)?
Grok Bot
Describe the Bug
In Grok Bot, the Gmail connector can’t see or act on messages in the Spam folder. When I asked my assistant to delete the spam in our support inbox, it searched and reported the folder as empty. Gmail itself showed 9 messages in Spam for the same account. Searches with in:spam, label:SPAM, and in:anywhere all return an empty result, even when searching for an exact sender that’s sitting in Spam. Search works normally for the inbox and all other folders. Because the empty result looks like “no mail,” the assistant gave me wrong information
Steps to Reproduce
Connect a Gmail account to a Grok Bot assistant through the Gmail connector.
Make sure the account has messages in Spam (confirm in the Gmail web app).
Ask the assistant to list or delete the messages in Spam.
The connector’s search comes back empty for in:spam, label:SPAM, and in:anywhere, so the assistant can’t find or delete them.
Expected Behavior
The connector should be able to list Spam messages and trash or delete them, perhaps through an includeSpam option like the existing includeTrash. At minimum, it should return a clear message that Spam is excluded, not an empty result that looks like “there’s nothing here.”

Windows 10/11

Additional Information
This happened on Sunday, Sep 27, 2026, around 12:30 PM CT, in a Grok Bot assistant connected to a Google Workspace Gmail account. The same connector finds messages in the Inbox, Sent, Drafts, and custom labels without trouble, and it can see Trash when its includeTrash option is turned on. Only Spam is invisible. What makes it confusing is that an empty result looks the same as “nothing here,” so the assistant told me my Spam folder was empty when it had 9 messages in it.
