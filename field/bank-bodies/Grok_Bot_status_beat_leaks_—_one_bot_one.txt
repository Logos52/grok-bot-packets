Because both bots share the same underlying agent, durable memory and conversation history contain information from both projects. The two projects can also have separate disk folders; the mix-up still occurs within the agent’s shared memory/history. Allow several Project B status beats to run, refreshing Project B in the shared agent memory/history. In Bot/Chat A, ask for Project A status, links, or an ambiguous request such as “continue.” Observe: Bot/Chat A receives Project B content instead of Project A content. Hey @LLMTester , thanks for the detailed report. What you are seeing is how a Grok Bot agent works today, rather than something broken in your setup! Each bot has one conversation and one memory, and that single history spans both its 1:1 chat with you and every group it is a member of. Group turns are tagged internally so the bot knows which room it is speaking in, but it is expected to draw on everything it knows, including its 1:1 history, and its saved memories belong to the bot, not to a chat. That means two long running projects on the same bot will cross over, exactly as you describe. The reliable way to keep Project X and Project Y separate right now is to give each project its own bot. If you want to stay on one bot, you can also ask it to keep Project Y notes in files under its project folder instead of saving them to memory, but that relies on the model following the instruction, so separate bots are the safer option. Chat scoped memory is something the team is actively working toward!
