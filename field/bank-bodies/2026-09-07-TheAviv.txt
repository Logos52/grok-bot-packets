## @deanrie 2026-09-06T17:23:27.384Z
Hey, thanks for the detailed report. This is a known issue with the native Open Files dialog on the Bot computer. What’s happening: the Bot desktop has a fixed screen with a dock along the bottom edge, and the Open/Cancel buttons in the dialog often end up right on top of that dock. Your click goes to the dock instead of the button, so the dialog stays open. The file itself is fine, which is why the same MP4 eventually uploaded to YouTube Studio and Instagram when the dialog happened to be positioned higher. Two ways to unblock yourself right now: Ask the Bot to attach the file without using the Open dialog at all. For example: “Use your browser tool to set the page’s file input directly with the DevTools command DOM.setFileInputFiles , pointing at /home/box/Downloads/Quest_for_the_Truth_suno_square.mp4 . Do not use the Open Files dialog.” This fully bypasses the dialog. If the site still requires the dialog, ask the Bot to drag the dialog up by its title bar (or double click the title bar to maximize it) so the Open button is above the dock, then click Open. To confirm this on your box, please send: A screenshot of the Bot screen at the moment it clicks Open (is the Open button sitting right on top of the dock icons at the bottom, or a bit above). The Request ID from that conversation right click the Bot message > Copy request ID. We’re tracking the dialog geometry issue and the no dialog upload path. I’ll reply here when there’s an update.
