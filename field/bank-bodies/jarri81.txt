### Jarri81 · 2026-09-05T14:26:06.606Z
Follow-up. Root cause (confirmed): Surfshark Antivirus real-time protection . Not the VPN, not web protection, not the accented PC name. Setup Result Surfshark VPN on, AV real-time off OK (~1.3s) Web protection on, real-time off OK (~3s) Real-time on temporarily unreachable (matches your ~11s vs 10s timeout) Real-time on + exclude only C:\Users\user\AppData\Local\Temp OK (~1–2s) Why Temp: each local-exec command writes a fresh ps-script-<uuid>.ps1 under %TEMP% and runs it via PowerShell. Surfshark real-time inspects that create/execute path and adds enough latency to miss the 10s agent wait. Excluding the Grok Bot install folder alone did not help. Surfshark also does not accept wildcard exclusions (e.g. ps-script-*.ps1 ), so we can’t narrow to just those scripts. Workaround we have now: exclude all of %TEMP% . That works, but it’s a security trade-off — we don’t want real-time AV to ignore everything created in Temp long-term. What would actually fix this properly (product side): Best: write local-exec scripts to a dedicated folder (e.g. under %APPDATA%\Grok Bot\tmp ) so users can exclude only that path while keeping Temp scanned; or Raise the local-exec wait timeout above ~11s so a normal AV scan doesn’t trip temporarily unreachable .
