### deanrie · 2026-09-05T16:01:24.206Z
Great work with the tests, that really closes the loop. The result with --disable-gpu-sandbox (the window stays up, 4 processes stay alive) confirms this: the Windows sandbox startup is crashing inside our helper processes, not in the runtime. --disable-gpu and --jitless don’t touch that path, so they couldn’t help. Your icacls output shows exactly the shape we were looking for: the Grok Bot folder inherited an app specific package SID the S-1-15-2-679848865-... line, the CodexSandboxUsers group, and an unresolved account, but it does not have ALL RESTRICTED APPLICATION PACKAGES S-1-15-2-2 . This exact combo, a package SID without an S-1-15-2-2 grant, makes Chromium sandboxed child processes crash with 0x80000003 for any Electron app installed under AppData\Local . This is tracked upstream in Electron, it’s not something specific to Grok Bot. These entries are usually left behind by another tool’s sandbox setup, and CodexSandboxUsers points to the Codex Windows sandbox. Thanks for the correction about Cursor, yep, yours is in C:\Program Files\cursor , outside that tree, so it isn’t affected. The blank window under --disable-gpu-sandbox is the same fault, it just made it to the next sandboxed process renderer, so there’s no need to chase the secret-store or box migration lines. The app finds an old saved login that it can’t read anymore, so it thinks you’re signed out, then it polls the server while signed out. Both stop after you sign in. Next, there are two paths, pick what fits your situation. Option A, if you still need Codex keep its entries, add the missing grant. This is additive and doesn’t require admin rights. In Command Prompt: icacls "%LOCALAPPDATA%\Programs\Grok Bot" /grant *S-1-15-2-2:(OI)(CI)(RX) /T icacls "%LOCALAPPDATA%\Programs\Grok Bot" /grant *S-1-15-2-1:(OI)(CI)(RX) /T To prevent it from coming back after an app update the updater rewrites the folder and re inherits ACLs from the parent, also grant the parent: icacls "%LOCALAPPDATA%\Programs" /grant *S-1-15-2-2:(OI)(CI)(RX) /T Option B, if Codex is uninstalled and not used cleaner, remove the cause instead of the symptom. Remove the orphaned entries and reset inheritance: icacls "%LOCALAPPDATA%\Programs\Grok Bot" /remove:g CodexSandboxUsers icacls "%LOCALAPPDATA%\Programs\Grok Bot" /remove:g *S-1-15-2-679848865-2255482870-1749806305-992153298-3878558069-768586100-158916155 icacls "%LOCALAPPDATA%\Programs\Grok Bot" /reset /T After either option, start Grok Bot normally without flags. You should get the sign in screen with the sandbox fully enabled. If it still won’t start after that, run it once with --no-sandbox just for diagnostics, don’t use that day to day, and send the output of icacls "%LOCALAPPDATA%" and icacls "%LOCALAPPDATA%\Programs" so we can see where the inherited entries come from.
