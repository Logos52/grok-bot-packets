Subject: [PATCH] Keep the gloss model loaded between lookups
MIME-Version: 1.0
Content-Type: text/plain; charset=UTF-8
Content-Transfer-Encoding: 8bit

Warming the model at startup only helps the first word. Ollama unloads an
idle model after 5 minutes, which is shorter than the gaps between lookups
when you're reading a page and then picking a word out of it — so the model
drops out mid-session and the next word pays the load cost all over again.

Send keep_alive with every request, defaulting to 30 minutes. It goes on
every request rather than just the warm-up because Ollama restarts the
unload timer from whatever value it saw last: a Define without it would
silently put the model back on the 5-minute default.

The right value depends on the machine — a large base model on a laptop is
worth unloading promptly, on a workstation worth keeping resident — so it's
configurable via --ollama-keep-alive and ollama_keep_alive. The value is
validated at startup, before the Ollama round-trip: it rides on every
lookup, so a typo Ollama rejects would otherwise fail every word once the
review screen is already open.

+// checkKeepAlive rejects a --ollama-keep-alive Ollama wouldn't understand.
+// It's checked here, next to the model preflight, for the same reason: the
+// value rides on every lookup, so a typo Ollama rejects would otherwise

+func checkKeepAlive(v string) error {
+	if v == "" {
+		// Left off the request entirely; Ollama applies its own default.
+		return nil
+	}
+	// Ollama accepts either a bare number of seconds or a duration string.
+	if _, err := strconv.Atoi(v); err == nil {
+		return nil
+	}
+	if _, err := time.ParseDuration(v); err == nil {
+		return nil
+	}
+	return fmt.Errorf("invalid --ollama-keep-alive %q: want a duration like %q, a number of seconds, 0 to unload immediately, or a negative value to keep the model loaded indefinitely", v, ollama.DefaultKeepAlive)
