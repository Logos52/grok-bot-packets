Feature request for product/service Chat Describe the request Title: Grok Bot: show and edit Bot role description in the info pane (match docs) Problem Official docs say role definition lives in the Bot description, edited via conversation details → Bot settings (name, label, description, notifications). See /docs/grok-bot/work and /docs/grok-bot/settings. On current desktop, opening the Bot info pane (name / Cmd+Shift+I) shows Details / Media / Computer with name, Add a label, and Routines — and no Bot settings entry and no description field. The documented edit path for the role brief is missing from the UI I actually get. Workaround: ask the Bot in chat to update its profile description (agent-side write). That can persist, but the user still cannot see or review the role text in the info pane. Role description is the standing job brief (what this Bot is for), not the same as historical Memory facts. What the docs say a role description is Across official docs, description is framed as a single durable role brief — not chat, not Memory logs, not a skill SOP: Describe the role in operational terms (owned outcome, what you pull/produce, approval boundary). Example: weekly account-health review → linked watch list; never contact customers without approval. (/docs/grok-bot/work) Put job, source systems, output format, and standing boundaries in the description. (/docs/grok-bot/use-cases) Update description for durable preferences/boundaries; use the conversation for task-specific asks (Edit a Bot). (/docs/grok-bot/work) Create-flow example Description: investigate with observability tools; preserve links/screenshots; never change production. (/docs/grok-bot/get-started) Assumption those docs leave: the role description is one editable string the user should be able to review and change in Bot settings next to name and label. There is no deeper schema in the docs — which makes a missing review/edit UI a product gap, not a missing “advanced role model.” Why Memory management is not this ask Forum topic: /t/grok-bot-desktop-ios-memory-management/168066 That FR is about viewing/editing accumulated profile + log facts. This FR is about the standing role brief (description): inspectable and editable where the product already documents Bot settings — adjacent to name and label, not a memory dump. Framing Keep chat for task-specific instructions; keep description for durable job + boundaries (per docs). The gap is discoverability and inspection, not inventing a new store. Chat-side profile update can stay as a power path; the default human path should match the docs. Request Expose Bot settings (or equivalent) from the info pane / name menu so description is visible and editable alongside name and label. Show the current description in plain language in Details (read view), not only after hunting a hidden editor. Keep label as the short chip; keep description as the longer operational role text. Optional: if chat-driven profile updates remain supported, reflect them immediately in that same UI. Why Without a visible description editor, users cannot confirm what role the Bot is actually holding, cannot iterate on the brief without asking the Bot to rewrite itself, and docs/UI disagree. Multi-Bot setups depend on clear, reviewable role boundaries; that fails if the role field is write-only via chat and invisible in the pane. Acceptance From the Bot info pane (or documented Bot settings entry point), user can view and edit description. After edit (UI or chat-side update), the pane shows the current description without opening files on the computer. Docs path and UI path match: name, label, description in one place. Distinct from Memory inspector: this is role/description only. Naming note Docs call this description (role / job). Add a label in the pane is the short title/label, not the role body. This FR is about the description field, not renaming Memory.
