## @health.ai_michael_gr · 2026-08-13T21:33:27.856Z

Describe the request We are rewriting the app around this. We need you to ship the primitives so a Bot is an object, not an unbounded thread. Problem Each Bot is one unbounded thread. Every turn reloads the full transcript (user messages, agent messages, tool dumps, screenshots, agent-to-agent pings). Obsolete traffic stays in the model context forever. There is no same-agent “new session,” no compact, and no way for the Bot to drop dead messages from what the model sees. The documented workaround is spawn another Bot. That explodes the roster, splits memory, and does not fix the product. Rewrite (what we are building against) Split a Bot into Identity, Working set, Archive. Stop treating the chat log as the Bot. Identity = name, description, memory, routines, skills, connectors. Survives forever. Working set = the only tokens the model sees this turn (current ask + live memory + pointed files). Archive = full transcript, user-visible, never auto-fed back into the model. New session: same Identity, empty Working set, previous thread goes to Archive. Compact: mark a message obsolete → it leaves Working set immediately. Keep it in Archive. Trigger compact when something dies, or when budget is hit, or when the user hits Compact. Not a cron that reloads the whole thread to “clean” it. Meter: tokens in Working set vs cap, and what was dropped. Required to manage a $200 cap. Agent-to-agent: shared files/memory are the bus. Pings are ephemeral; they must not accumulate in Working set. Default system prompt: do not re-inject Archive. Hide/delete is not compaction. Spawning a clone is not compaction. UI: Compact and New session on this Bot (header), plus a Working-set size chip. Success: one CoS, weeks of work, thin Working set. Failure: clone army or daily full-reload jobs. Durable state that must survive compact/new-session: profile, memory, routines, skills, shared computer files. Chat history must not be that store. Not asking for: more Bots; hide/delete as the compaction tool; a daily cron that reloads the full thread to “clean” it.
