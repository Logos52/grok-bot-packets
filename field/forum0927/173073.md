# 1Password plugin MCP fails to start: spawn 1password-mcp EACCES

## Post 1 @mason-feature-slayer · 2026-09-26T15:52:17.240Z
Where does the bug appear (feature/product)?

Cursor IDE

Describe the Bug

The official 1Password Cursor plugin MCP server never connects. Cursor creates the client, then the shared MCP process fails while spawning the server:

Connection failed: spawn 1password-mcp EACCES

The spawn policy log says sandboxed=false and sandboxReason=controls_disabled, so this is not the MCP sandbox blocking the process. The plugin mcp.json starts the bare command 
1password-mcp
 (no absolute path). The 1Password tools stay unavailable.

Steps to Reproduce

Install the 1Password plugin from the Cursor Marketplace (server id plugin-1password-1password).

1Password desktop 8.12.36 is installed. The MCP binary inside the app is present and executable: /Applications/1Password.app/Contents/MacOS/1password-mcp (-rwxr-xr-x).

Start Cursor, or reload MCP servers.

In the MCP logs, createClient reports success, then stdio connect fails with spawn 1password-mcp EACCES.

Expected Behavior

The 1Password plugin MCP server should start and expose its tools. The desktop app binary is executable, and the spawn log shows the sandbox is disabled, so the server should connect instead of failing with EACCES.

Plugin mcp.json command is exactly “1password-mcp” with no args and no absolute path.

/Applications/1Password.app/Contents/MacOS/1password-mcp exists and is -rwxr-xr-x (owner dgitman:admin, about 4 MB, dated Sep 8). It has a Homebrew Cask quarantine xattr.

/usr/local/bin is drwx------ root:wheel (mtime Sep 21 15:45). The user cannot list it, and ls /usr/local/bin/1password-mcp returns Permission denied. That matches the EACCES from Cursor’s stdio spawn, which looks up 1password-mcp on PATH.
