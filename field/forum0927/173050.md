Describe the Bug

Grok Bot on Linux changes my XDG default 
text/html
 handler to 
grok-bot.desktop
 every time I launch it.

I use Brave as my default browser:

xdg-mime default brave-browser.desktop text/html

xdg-open https://example.com

text/html
 becomes:

text/html=grok-bot.desktop

and 
xdg-open
 opens Grok instead.

How can I prevent Grok Bot from registering itself as the default HTML handler while keeping its 
grokbot://
 and 
sand://
 handlers?

You’re right, Grok Bot shouldn’t touch your text/html default. It happens when Grok Bot registers its grokbot:// and sand:// links on startup. On GNOME-based desktops (GNOME, Cinnamon, MATE), the system tool it uses for that also sets the app as the HTML handler. This is a known issue and I’ve added your report to it.

In the meantime, you can restore Brave after Grok Bot has started:

xdg-mime default brave-browser.desktop text/html

If you’d rather not do that by hand, a small launcher script that starts Grok Bot, waits a few seconds, and then runs that command will keep Brave as your default. The grokbot:// and sand:// links will keep working either way.
