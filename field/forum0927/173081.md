Steps to Reproduce

Use this as Steps to reproduce. It is the same failure, shrunk to something a Cursor reviewer can run.

Environment

• Cursor agent / Grokbot with file-write (or apply-patch) + git

• A source file larger than a small patch (100KB+ is how we hit it; ParserCore was ~173KB)

• git remote over HTTPS (not SSH), no gh auth / credential helper

Steps

Open a git repo with a large text file, e.g. copy any ~150KB .c / .py / .ailang to big.ailang.

Ask the agent, in one turn:

│ Replace big.ailang with a full valid rewrite of the same file (keep it ~150KB). Then git add big.ailang, commit, and git push over HTTPS.

After the agent says it wrote and pushed, do not trust the chat. On disk / in git run:

wc -c big.ailang

head -c 200 big.ailang

git show HEAD:big.ailang | wc -c

git show HEAD:big.ailang | head

If push is involved, also run:

git push origin HEAD

Expected

• big.ailang on disk and in HEAD is the full ~150KB source.

• git push authenticates and updates the remote.

Actual

• File on disk / in the commit is a 34–68 byte placeholder, not the body, for example:

• 
@file
:/tmp/pc_forparen_only.ailang

• LOAD_FROM_FILE:/tmp/aimacro_assemble_tip/py2aim_tip_direct.push.json

• @/workspace/repos/…/Library.AIMacroCodeGen1.ailang82

• The path is on the agent VM, so a pull on another machine cannot expand it.

• HTTPS push: could not read Username for 
https://github.com
.

• MCP/push of small files still works; large bodies do not, so the agent starts chunking (restore_staging micros) or committing the stub.
